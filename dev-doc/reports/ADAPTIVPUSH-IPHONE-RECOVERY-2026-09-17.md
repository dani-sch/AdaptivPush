There is no device-storage capture proving which mechanism first removed the visible session; password invalidity and actual token deletion are not inferred.

Removing that blanket focus-disable allows the drag to reveal one action without logging or deleting a set. Physical native gesture certification remains open.
4. **Blank inputs inherited `unknown`/`none`.** Active initialization based load unit on whether a planned amount existed. Preserved older drafts and completed reconstruction carried that metadata; the card intentionally printed nothing for unit none. The LOAD header ignored its prior label metadata. This accounts for differences between otherwise pound-based cards with and without load history.

## Implemented behavior

`AuthProvider` and the pure session recovery controller own hydration, recoverable failures, definitive sign-out and account changes. Failed hydration retains only scoped local ownership, with protected workout actions paused; stale reads cannot restore another account after a newer sign-in/sign-out. Native AppState starts/stops token refresh and retries on foreground. Expiry triggers recovery, and the root guard no longer equates failed hydration or profile availability with sign-out. Authentication storage is not cleared as a debugging action. The auth callback defers program refresh outside the SDK callback lock.

The request wrapper classifies native Expo connection failures and status-zero AuthRetryableFetchError as retryable connectivity failures, distinct from credentials, timeout, schema and authorization. Bounded fetch settles even if a native transport ignores abort. The classifier and actionable login message fix the failure, not LogBox suppression. The screenshot's diagnostic line is now `utils/supabaseResilience.ts:308`; password sign-in reporting remains `app/(auth)/login.tsx:97` (catch path 131). Diagnostics contain bounded status/category/operation fields, never credentials or tokens.

The unsafe test process was stopped and replaced with `npm run web:local`, which binds 8082 to loopback only and sets local overrides only in its child. Native client configuration rejects loopback backends with guidance to the hosted Expo server or a verified LAN test build. The user's hosted Metro process on 8081 was preserved. A fresh iOS bundle from 8081 includes session recovery, native loopback protection, removal checks and uppercase labels, contains the hosted URL and no localhost database URL, and contains no privileged values from .env. Its observed SHA-256 is `037991df254910a496948283162d457e3880334b535920e24f4293ab12b551d0`; a dev bundle hash is capture-specific, not a signed release identity.

Removal capability now has checking, supported, unsupported and failed states, with explicit retry on both screens. Failed metadata checks propagate typed failures rather than substituting empty masks. Requests are owner-bound and discarded on account changes; refresh/reconnect checks again. Removal remains disabled without the exact integer-1 contract. Focus no longer disables the whole row; unavailable/read-only transitions close open actions. Existing scope sheet, stable identities, tombstones, recorded-result warning, extras/empty states, single-open-row coordination, transparent backdrops and atomic broader scope are retained.

Blank active prescriptions receive external LB input metadata without creating an actual amount or logging a set. Existing frozen prescriptions and pending payloads are not rewritten. Shared row/header presentation uses LB/KG, assistance marks and BW. An unknown historical numeric measurement shows UNIT? rather than being silently relabelled. Completed reconstruction retains effective saved unit/type metadata for unperformed rows, while recorded actuals remain authoritative. Selecting and typing a blank completed load uses corresponding input metadata; actual historical units remain unchanged. Less frequent settings remain in set options.

Active drafts and exact finalization/swap/correction operations retain their owner-scoped stores. Finalization additionally checks the matching authenticated owner and pins the request token. Unsubmitted completed-editor text/removal intent now has a separate owner/session/revision-scoped serialized store; it survives reload and legitimate reauthentication without replacing a pending exact correction payload. Explicit Cancel discards unsubmitted edits. A changed server revision does not silently apply old edits.
